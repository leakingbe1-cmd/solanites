# Solanites Creature Studio

Art direction and production for redesigning **all 28 species × 4 stages (112 artworks)** of the Solanites collection. Work happens on the `creature-studio/art-direction` branch and only adds files under `docs/creature-studio/`; it does not change application code, shared components, data or the website.

## Status

| Milestone | Scope | Status |
|---|---|---|
| **A. Audit and art direction** | inventory, asset map, art bible, priorities, prototype briefs, evolution and animation guidelines | **Delivered, awaiting review** |
| B. Prototype approval | Velynx, Mossling and Cryovant redesigned (4 stages each) + comparison boards | Blocked on approval to spend image-generation credits |

| D. Animation preparation | per-creature animation plan, performance budget, rollout | First draft in `evolution-and-animation.md` §4–§6 |

## Files

| File | What it is |
|---|---|
| [`inventory.md`](inventory.md) | Master inventory of every species, per-creature audit (8 points each), open decisions, redesign priority order |
| [`asset-map.json`](asset-map.json) | Machine-readable mapping: species → metadata, original renderer, references, raster slot, redesign candidate path and status, for all 112 stages. Generated by `tools/build-asset-map.mjs` |
| [`art-bible.md`](art-bible.md) | The rules: shape, anatomy, faces, linework, shading, materials, light, colour, elements, rarity, presentation, thumbnail tests, AI-output checklist |
| [`prototypes/`](prototypes/) | Briefs and generation prompts for the three prototypes, the Velynx evolution sheet, and the generation plan |
| [`evolution-and-animation.md`](evolution-and-animation.md) | Evolution rules, animation tiers, per-creature recommendations, performance budget, rollout plan |
| [`baseline/`](baseline/) | The shipped vector art, rendered from the code, one sheet per rarity: the "before" for every comparison |
| [`tools/`](tools/) | `render-baseline.mjs` (re-render the originals) and `build-asset-map.mjs` (rebuild the asset map) |

## Working rules

- **Originals are never overwritten.** The shipped artwork is code in `src/components/creature/species/`; this branch does not modify it, and it remains the fallback for any stage without approved raster art. `tools/render-baseline.mjs` re-renders it at any time.
- **Review area first.** Candidate images go to `art/creature-studio/<id>/<n>-<stage>.png` (review only, not read by the site). A file is copied into `art/creatures/` (what `npm run art:build` publishes) only when the design is approved **and** integration is agreed with the website builder.
- **Data is not changed.** Names, ids, rarities, elements, discovery rules, stage count and timings stay as they are in code. Proposed data or text changes (for example the style prompt in `creatureDesigns.json`) are listed in `inventory.md` §4 for the builder to apply.
- **No paid generation without approval.** Runway image or video credits are spent only after explicit sign-off of a stated budget.
- Every accepted image records model, prompt, seed and any paint-over notes in `asset-map.json`.

## Regenerating

```bash
npm ci
node docs/creature-studio/tools/build-asset-map.mjs
NODE_PATH=$(npm root -g) node docs/creature-studio/tools/render-baseline.mjs /tmp/baseline   # needs Playwright + Chromium
```

## Coordination with the website builder

Integration needs nothing from this branch beyond the image files: the existing raster pipeline and `CreatureArt` fallback already support per-stage replacement. Items that do need the builder: the four decisions in `inventory.md` §4 and animation steps 2–4 in `evolution-and-animation.md` §6.
